Overview

David W. Matula discovered a beautiful bijection between positive integers and rooted trees. This encoding uses prime factorization to recursively build tree structure:

The Bijection
  • 1 ↔ single node (leaf)
  • prime(k) ↔ tree with one child encoding k
  • p × q ↔ tree with children for p and q
Examples
  • 1 = o (leaf)
  • 2 = (o) (prime(1))
  • 4 = (o o) (2×2)
  • 6 = (o (o)) (2×3)

Key Insight: Trees Encode Graphs

We extended Matula's tree encoding to arbitrary graphs by observing that every graph decomposes into:

  1. Block-cut tree: How 2-connected components connect (topology)
  2. Block constructions: What each 2-connected block actually is

This decomposition is itself a tree — and can be encoded as a Matula number!

Understanding Blocks & Cut Vertices

Before we can encode graphs as numbers, we need to understand how graphs decompose into simpler pieces. This is the key insight that makes our encoding work.

The Big Picture

Every graph breaks down into two things:

  1. Topology — How the pieces connect (the "skeleton")
  2. Construction — What each piece actually is (the "flesh")

What is a "Block"?

In graph theory, a block is a maximal subgraph with no cut vertex. There are two types:

True 2-Connected Blocks

These are the "robust chunks" — subgraphs where removing any single vertex still leaves the rest connected.

Intuition: In a road network, this is a region where you can always find an alternate route if one intersection is closed.

  • Triangle (K₃): Remove any vertex → still connected
  • Square (C₄): Remove any vertex → still a path
  • K₄, C₅, etc.: Multiple redundant paths
Trivial Blocks (Bridges)

A single edge connecting two vertices is called a bridge. It's technically a "block" in the decomposition, but it's not 2-connected.

Why? If you remove either endpoint, there's nothing left to be "connected"!

  • Single edge (K₂): The degenerate case
  • Bridges are the "weak links" in a graph
  • They appear as separate blocks in the decomposition

Why include trivial blocks?

The block-cut decomposition needs to account for every edge. A bridge (single edge not part of any cycle) forms its own trivial block. This ensures the decomposition captures the complete structure of the graph, including its weak points.

What is a "Cut Vertex"?

A cut vertex (or articulation point) is a vertex whose removal disconnects the graph. It's a "chokepoint" or "bridge" between blocks.

The Block-Cut Tree

The block-cut tree shows how blocks connect through cut vertices. It's always a tree (no cycles), which makes it perfect for encoding!

Block Construction: What IS Each Block?

Once we know the topology (how blocks connect), we need to know what each block actually is. Two graphs can have the same topology but different blocks:

Same Topology

Both are: "two blocks sharing a cut vertex"

Different Constructions

Triangle + Triangle (bowtie)
vs
Triangle + Square

The construction of a block describes its internal structure. For example:

Block Type Description Construction Matula
K₂ trivial Single edge (bridge) — NOT 2-connected 2
K₃ 2-connected Triangle — remove any vertex, still connected 14
C₄ 2-connected Square (4-cycle) — remove any vertex, still a path 30
K₄ 2-connected Complete graph on 4 — highly redundant 134

Putting It Together

The Encoding Recipe

  1. Find the blocks — Identify 2-connected components and bridges
  2. Find the cut vertices — Where do blocks connect?
  3. Build the block-cut tree — This is the topology
  4. Encode each block — What is each block? (construction)
  5. Combine into one tree — Topology + constructions = Matula tree

Why This Matters

This decomposition is powerful because:

  • It's unique — Every graph has exactly one block-cut tree
  • It's a tree — Trees can be encoded as Matula numbers!
  • It's hierarchical — We can encode topology and construction separately
  • It's meaningful — The structure reveals graph properties

The Red Node Encoding

Potentially Novel Concept

The "red node" is a semantic boundary in the Matula tree that separates topology from construction. This framing appears to be new.

Visualize a graph's encoding as a Matula tree where one conceptual level is "red":

        BLACK (root)
           │
      [topology]     ← How pieces connect (block-cut tree)
           │
         RED         ← Semantic boundary
           │
    [construction]   ← What each piece is (block structure)

The Collision-Free Scheme

Our initial encoding had collisions (e.g., K₂+vertex and P₃ both mapped to 6). We developed a collision-free variant using tree depth:

Graph Type Matula Tree
Single vertex connected 2 (o)
Two isolated disconnected 4 (o o)
K₂ (edge) connected 3 ((o))
K₂ + vertex disconnected 6 (o (o))
2K₂ disconnected 9 ((o) (o))
P₃ (path) connected 23 (((o) (o)))
K₃ (triangle) connected 43 ((o (o o)))
K₁,₃ (star) connected 103 (((o) (o) (o)))
P₄ connected 347 (((o) ((o) (o))))
K₄ connected 757 ((o ((o o o))))

Key rule: Connected graphs have prime Matula numbers (single child at root = wrapped). Disconnected graphs have composite Matulas (multiple children).

Tree ↔ Graph Operations

Arithmetic Has Graph Meaning

Every operation on Matula numbers corresponds to an operation on the encoded graph.

Arithmetic Tree Operation Graph Operation
prime(n) Wrap: add parent with single child Connect at cut vertex
primeIndex(p) Unwrap: remove single-child root Disconnect at cut vertex
n × m Siblings: children of same root Disjoint union
n / p Remove one child subtree Remove component
isPrime(n) Root has exactly one child Graph is "atomic" connected
factorize(n) Get root's children Get components/blocks

Novelty Assessment

Based on OEIS research and literature review:

Known Matula-Goebel Numbers

The bijection between integers and rooted trees via prime factorization (OEIS A061773) is well-established since Matula (1968) and Goebel (1980).

Known Block-Cut Decomposition

The block-cut tree structure and algorithms (Hopcroft-Tarjan) are standard in graph theory.

Potentially New Red Node Encoding

Using Matula trees to encode graphs (not just trees) via block-cut decomposition, with a semantic "red node" boundary, appears novel.

Potentially New Collision-Free Scheme

Using tree depth to distinguish connected vs. disconnected graphs, and path vs. star topology via nesting structure.

Potentially New Operation Correspondence

The systematic mapping of wrap/unwrap to connect/disconnect at cut vertices, and multiplication to disjoint union.

Potentially New Graph DSL

A construction language where algebraic expressions directly map to graph operations and Matula encodings.

Related OEIS Sequences

  • A061773 - Matula-Goebel numbers for trees
  • A000088 - Number of graphs on n unlabeled nodes
  • A001349 - Number of connected graphs on n nodes
  • A127301 - Maps plane trees to Matula-Goebel numbers

The sequence of valid graph-encoding Matula numbers (2, 3, 4, 6, 9, 23, 43, 103, ...) does not appear in OEIS and could be submitted as a new sequence.

Promising Research Directions

1. Graph Isomorphism via Arithmetic

Two graphs are isomorphic iff they have the same Matula encoding. Can number-theoretic properties help detect isomorphism efficiently?

2. Graph Properties from Numbers

What graph properties can be read directly from the Matula number? Connectivity = primality. What about planarity, chromatic number, etc.?

3. Hierarchical Decomposition

Multiple "red levels" could encode nested community structure, modular decomposition, or multi-scale graph features.

4. GCD and LCM for Graphs

What is gcd(G₁, G₂)? The "largest common substructure"? Could define a partial order on graphs.

5. Extension to Other Structures

Directed graphs, hypergraphs, simplicial complexes — can similar encodings be developed?

6. Compression & Density

The encoding is sparse (~0.1% of integers are valid). Can we define a dense ranking while preserving structure?

Open Questions

  1. What is the asymptotic density of valid graph-encoding Matula numbers?
  2. Is there a polynomial-time algorithm to test if a number is a valid graph encoding?
  3. Can we characterize which Matula trees correspond to planar graphs?
  4. What is the relationship between graph automorphisms and Matula tree symmetries?
